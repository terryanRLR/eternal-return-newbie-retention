# 04. 튜터 피드백 & KPT 회고

원본: Notion 페이지 "[10팀] 쉽(10)네? - [게임] 이터널리턴 데이터 분석" 중 서면 피드백 / KPT 회고 섹션을 정리.

## 메인 튜터 피드백 — 정강민 튜터

### 1. 데이터 EDA 및 전처리
- 캐릭터·지역 코드 매핑과 패치 전후·군집용 파생변수 설계로 전처리 근거가 명확함.
- **뉴비 정의를 `accountLevel≤60 AND rankPoint=0 AND 일반 스쿼드`로 보정(코발트 모드 과대분류 교정)한 트러블슈팅이 백미** → `03_issues_and_troubleshooting.md` #1.
- 개선 필요: 60레벨 컷 근거를 분포·교차표로 박제하지 않음. 표본 한계(리텐션 분석 불가)를 EDA 결론으로 먼저 명시했어야 함.

### 2. 모델링 및 평가
- 계정 기준과 K-Means 행동군집을 목적별로 분리하고, 사분면 분석의 한계를 인정한 뒤 IsolationForest 다변량 이상치 + SHAP으로 연결한 절제된 설계가 좋음 → `03_issues_and_troubleshooting.md` #5, #6.
- "같은 이상치도 원인이 달라 처방이 다르다"는 해석이 **가장 데이터분석가다운 대목**으로 평가됨.
- 개선 필요: **K-Means k 결정 근거(실루엣/엘보우)와 개선필요군 근거, SHAP 산출물이 슬라이드로 뒷받침되지 않아 검증 과정이 구두로 흘러감** → `03_issues_and_troubleshooting.md` #7의 잔여 이슈.

### 3. 결과 해석 및 보고
- 경영진·기획자·밸런스팀·유저 4관점 해석 매트릭스로 한 로그를 이해관계자별 액션으로 번역한 기획·스토리가 (동기수강) 팀 중 최상위.
- 개선 필요: **"2주 데이터 단정 과다"의 모순을 받아들여 "제약 내 점검 신호" 톤을 일관 유지했어야 함** → `03_issues_and_troubleshooting.md` #18.
- 고위험 캐릭터의 실제 패치노트·여론 대조는 이상치 탐지의 자연스러운 사후 검증이었는데 "재밌는 접근"으로만 남기고 실제로 진행하지 않은 점이 아쉬움 → `03_issues_and_troubleshooting.md` #17.

### 4. 종합 피드백
- 문제정의 → 뉴비 정의 보정 → 모델링 → 4관점 해석 → 대시보드 액션으로 이어지는 서사 연결이 가장 매끄럽고, 기획·스토리텔링이 최상위.
- 다음 개선 3가지:
  1. 결론의 톤 일관성("제약 내 점검 신호")
  2. 인사이트 검증 설계 한 장(패치노트 대조·리텐션·A/B 가설)
  3. 그래프별 결론 캡션 추가

> 서브 튜터 피드백은 원본 문서에 내용이 채워지지 않은 상태(공란)였습니다.

## KPT 회고

### Keep — 개인 성과
- **황현웅**: 승률·픽률 2변량 비교에서 그치지 않고 평균등수·생존시간·딜량·킬수를 종합한 다변량 분석으로 확장. 전체 유저와 초보 유저를 나누어 비교하며 초보 정착 관점을 분석에 반영. → `03_issues_and_troubleshooting.md` #5와 직접 연결.
- **박근우**: "뉴비 유저"의 정의 기준을 직접 수립(플레이 횟수·계정 생성 시점 등 실데이터 기준 검토). 뉴비/일반 유저 간 사망 지역 분포 차이를 바그래프로 확인.
- **안영진**: 생소한 게임 도메인에서 문제 제기 → 주제 선정 → 가설 → 전처리 → KPI 선정 → 분석 → 인사이트 → 대시보드 → 발표자료까지 전 과정 협업 경험. 코드/장소 삽입 실수로 인한 디버깅 경험도 공유.
- **이태민**: 팀 분석 결과를 통합 대시보드로 시각화하는 역할 분담 협업, 보는 사람 입장에서 시각화를 단순화한 직관적 대시보드 구성에 기여.
- **이혜진**: (원본 문서 공란)

### Keep — 팀 성과
- 로그 분석 → 대시보드 제작 → 발표자료 구성까지 전 과정 협업 완료.
- 뉴비 정의, 밸런스 분석, 유저 행동 분석, KPI 구성 등 각자 주제를 구체화하며 방향 설정.
- 생소한 게임 도메인에서도 데이터 기반 문제 정의 및 분석 기준 수립.
- 기획자·운영자 관점에서 활용 가능한 지표를 고민한 대시보드 구성.
- 짧은 기간 내 전처리·분석·시각화·발표 전 과정 완주.

### Problem — 개인 아쉬움
- **황현웅**: 발표 중 개인 환경 문제로 호흡 조절 실패 → 대시보드 파트 발표 분량 조절 실패 → 다른 파트 평가에도 영향.
- **박근우**: 집단 간 차이 발견까지는 잘했지만 뉴비 정착안에 대한 결과 도출이 부족, 대시보드가 EDA 시각화 나열에 그침 → `03_issues_and_troubleshooting.md` #16.
- **안영진**: 세부 루트/아이템/스킬 등 더 깊은 기능을 넣고 싶었으나 도메인 이해 부족으로 구현하지 못함. 본인 역할에 집중하다 팀 내 소통에 소홀했던 점 반성.
- **이태민**: 모델/지표 원리를 충분히 이해하지 못한 채 결과를 받아쓴 부분, 도구 의존도가 높아 직접 역량 검증이 어려웠던 점.
- **이혜진**: (원본 문서 공란)

### Problem — 팀 차원 아쉬움
- 분석 결과와 대시보드 기획 의도가 긴밀하게 연결되지 못함 — 일부 결과가 EDA 시각화에 가까움.
- 게임 도메인 사전 이해 부족으로 지표 해석·우선순위 결정에 많은 시간 소요.
- 분석 기간이 약 2주로 짧아 장기 메타 변화나 유저 행동 흐름을 안정적으로 파악하기 어려움.
- 분석 결과가 실제 운영 개선/기획 의사결정으로 이어지도록 구조를 더 명확히 설계하지 못함.

### Try — 다음에 시도할 것
- 대시보드 제작을 넘어 사용자 세분화, 이탈 예측, 추천 시스템 등 데이터 기반 의사결정형 프로젝트 수행.
- 프로젝트 초기 단계에 도메인 조사·유사 사례 분석을 충분히 진행해 해석 정확도 향상.
- 분석 목적과 최종 결과물을 먼저 정의한 뒤 필요한 데이터·지표를 역산해 설계하는 순서로 진행.

## 이 문서와 트러블슈팅 로그의 관계
튜터 피드백과 KPT는 "무엇이 문제였는가"에 대한 **팀 스스로의 진단**이고, `03_issues_and_troubleshooting.md`는 그 진단을 **코드·데이터·슬라이드 근거로 역추적해 재구성**한 것입니다. 두 문서를 같이 보면 "팀이 자체적으로 인지한 문제"와 "코드/산출물로 실제 검증 가능한 문제"를 구분해서 볼 수 있습니다.
