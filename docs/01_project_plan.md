# 01. 프로젝트 기획서

> 원본: Notion "쉽(10)네? 실전 프로젝트 기획서" — 팀 10조, 이 문서는 원본 기획 문서를 레포용으로 재정리한 것입니다.

## 팀 정보
- 팀명: 쉽네? (10조)
- 팀원: 황현웅, 박근우, 안영진, 이태민, 이혜진
- 프로젝트 기간: 실전 프로젝트 2026-05-27 ~ 2026-06-12 (12 Day)

## 프로젝트 제목
게임 로그 데이터 기반 운영 인사이트 분석 대시보드 구축 — **이터널리턴 초보 유저 이탈 진단과 정착 솔루션**

## 목표
이터널 리턴 유저 플레이 데이터를 활용해 유저의 플레이 패턴과 매칭 결과에 영향을 주는 요인을 분석하고, 특히 **초보/저성과 유저가 언제·어디서·왜 이탈하는지**를 데이터로 진단한다. 최종적으로 임원진 / 기획자 / 밸런스팀 / 유저, 4개 관점의 대시보드로 결과를 전달하고 정착률 향상 방향을 제안하는 것을 목표로 한다.

> 참고: 기획서 초안에는 "Tableau + Streamlit" 조합이 활용 계획으로 적혀 있으나, 최종 산출물은 **Chart.js 기반 정적 HTML 대시보드 2종(사내 종합용 / 유저용)** 으로 구현되었다. 툴 선택이 기획 단계에서 실행 단계로 넘어가며 변경된 것으로 보이며, 자세한 배경은 `04_tutor_feedback.md` 및 `03_issues_and_troubleshooting.md`를 참고.

## 핵심 분석 질문 (4관점)
| 관점 | 질문 |
|---|---|
| 경영진 | 게임의 전체 활동성과 메타 흐름은 어떤가? |
| 기획자 | 뉴비 유저는 언제, 어디서, 왜 이탈하는가? |
| 밸런스팀 | 특정 캐릭터가 메타에 과도하게 집중되어 있는가? |
| 유저 | 자신의 플레이에서 어떤 부분을 개선할 수 있는가? |

## 문제 정의
- 이터널 리턴은 파밍·제작·이동·성장·교전 판단·팀 플레이를 동시에 요구하는 복합 전략 게임 → 숙련자에게는 재미지만 초보자에게는 높은 진입 장벽.
- 초보 유저가 초반에 빠르게 탈락하면 핵심 재미를 경험하기 전에 이탈할 가능성이 높음 → 유저 정착률 저하로 직결.
- 따라서 실제 플레이 데이터로 (1) 초보가 어려움을 겪는 구간, (2) 부담이 큰 캐릭터/플레이 방식, (3) 생존·성과가 높아지는 조건을 규명하는 것이 목표.

## 데이터 개요 (기획 단계)
- 원본 파일명(기획서 상): `EternalReturn_kakaogames_2024.csv`
- 기획서 상 명시 기간: 2024-07-08 ~ 2024-08-08 (※ 실제 최종 분석에 쓰인 기간과 다름 — 아래 참고)
- **최종 분석에 실제로 사용된 기간: 2024-05-30 ~ 2024-06-12** (약 2주, 패치 22.1 → 23.0 전환 포함)
- 최종 데이터 규모: 총 관측치 204,425 / 컬럼 228개 / 매치 11,075건 / 유저 92,705명

> ⚠️ **기획서-실행 간 불일치 기록**: 기획서 초안의 데이터 기간(07/08~08/08)과 최종 산출물(슬라이드 04 "데이터 개요")에 적힌 기간(05-30~06-12)이 다릅니다. 이는 기획서가 프로젝트 착수 전 일반 템플릿을 바탕으로 작성되었고, 실제 제공된 원본 CSV의 실 데이터 기간에 맞춰 분석 범위가 확정된 것으로 추정됩니다. 원본 CSV가 레포에 없어 확정할 수는 없으니, 팀원 확인이 필요합니다. (`03_issues_and_troubleshooting.md` #10 참조)

## 주요 원본 컬럼 (기획서 예시)
`userNum`, `characterNum`, `matchingMode`/`matchingTeamMode`, `gameRank`, `victory`, `playerKill`, `playerAssistant`, `playerDeaths`, `monsterKill`, `bestWeapon`, `playTime`/`duration`, `premadeMatchingType`, `damageToPlayer`, `damageFromPlayer`, `healAmount`, `routeId`/`routeSlotId` 등.

실제로 전처리에 쓰인 전체 컬럼 목록과 대시보드별 사용 컬럼은 `02_analysis_pipeline.md` 및 `data/README.md` 참고.

## 전처리 계획 (기획 단계 원안)
- `head()`/`info()`/`describe()`로 구조 점검, 결측·이상치·중복 확인
- 핵심 식별 컬럼(유저번호/캐릭터번호/매칭모드/순위) 결측 → 제거
- 행동 지표(킬/어시스트/피해량 등) 결측 → 0 또는 중앙값 대체 검토
- 범주형(루트/무기/파티유형) 결측 → `Unknown` 처리
- 이상치는 단순 제거하지 않고 IQR/3-sigma/도메인 기준으로 판단
- 파생변수: KDA, 승률, 평균순위, 생존시간 구간, 초보 유저 구분, 교전 성향, 성장 지표

> 이 원안이 실제로 어떻게 구현/수정되었는지는 `02_analysis_pipeline.md`(파이프라인)과 `03_issues_and_troubleshooting.md`(트러블슈팅)에서 코드·근거와 함께 추적합니다.
